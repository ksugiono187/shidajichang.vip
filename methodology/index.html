TESTING METHODOLOGY

节点测试与数据采集说明

实事求是，公开说明我们如何进行节点体验测试与数据整理。

一、测试环境说明

本站的测试数据并非来源于 24 小时全自动天眼监控集群，而是编辑小组成员在实际使用过程中，通过个人家用宽带环境进行的人工抽样记录：

  • 上海电信环境：上海电信 1000M FTTH 宽带，用于测试常用节点的 Ping 延迟与首帧响应。
  • 北京联通环境：北京联通 500M FTTH 宽带，用于校对北方地区连接质量。

二、测试指标的采集方式

1. 晚高峰抽样延迟 (20:00 - 23:00)
在黄金拥堵时段使用客户端手动测试常用节点的 TCP / ICMP 响应，记录平均延迟范围。
2. 4K 视频体验
在 YouTube 播放 4K 视频，记录缓冲区加载时间与流畅度体验。
3. 下行带宽峰值
使用 Speedtest CLI 在突发测试中测得最高下行峰值速度。
4. 解锁测试
手动测试 OpenAI (ChatGPT)、Claude 及 Netflix 的访问体验。

三、评分算法与权重规则 (Score Engine)

本站拒绝凭主观印象随意打分，所有服务商的综合得分由基础抽样数据集结合公开加权算法引擎（Score Engine）归一化计算得出：

1. 线路稳定性 (Stability, 权重 40%) Ping 延迟 (40%) + 丢包率 (30%) + 带宽峰值 (30%)
2. 协议与全端适配 (Compatibility, 权重 20%) VLESS-Reality / Hysteria2 / Sing-box / Clash 支持度
3. IP 纯净与解锁 (Unlock, 权重 20%) Netflix 4K / OpenAI (ChatGPT) / Claude 解锁成功率
4. 性价比与透明度 (Value, 权重 20%) 单 G 流量单价 + 流量倍率真实透明度评估

加权计算公式：Overall Score = (Stability × 0.40) + (Compatibility × 0.20) + (Unlock × 0.20) + (Value × 0.20)

四、客观性承诺

因网络波动受本地 ISP、线路出口状况及时间节点影响很大，单次测试数据仅代表特定时间段的样本快照。我们不伪造数据，也不夸大体验，尽量如实呈现。
